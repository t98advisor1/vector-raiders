# 문항 세트(md) 만들기: AI에게 요청하는 방법

이 게임의 목적은 **개념 학습**과 **직접 조작으로 개념 이해하기**입니다. 문제는 그 이해를 확인하는 마지막 단계입니다.
그래서 AI에게도 "문제부터"가 아니라 **개념 → 조작 그림 → 문항** 순서로, 세 단계로 나눠 요청합니다.

| 단계 | AI가 만드는 것 | 선생님이 확인할 것 |
|---|---|---|
| 1. 설계표 | 상자 9개의 개념, 핵심 카드, "무엇을 움직이면 무엇이 보이는가" | 개념 순서와 조작 아이디어가 수업 의도와 맞는지 |
| 2. 핵심 카드 | 카드 10장 안팎 + 카드마다 조작 그림 | 설명이 정확한지, 그림을 움직이면 개념이 보이는지 |
| 3. 문항 | 27문항 + 문항마다 조작 그림·조작 안내 | 정답, 그림 수치가 문제와 맞는지 |

## 준비물

1. 교사 화면 → 📤 올리기 칸 → **📄 형식 예시 받기**로 `geo-3-1.md`를 받습니다. AI가 이 파일의 모양을 그대로 따라 합니다.
2. 교과서에서 만들 소단원의 개념·예제·문제 쪽(PDF나 사진)을 준비합니다.
3. 사진이나 교과서 그림처럼 **조작 그림으로 만들 수 없는 것만** 교사 화면의 **🖼️ 그림 파일 올리기**로 먼저 올립니다. 올리면 나오는 `그림: /img/…` 줄을 AI에게 함께 알려 줍니다. 그래프·도형·벡터는 그림 파일 대신 조작 그림으로 만드세요(학생이 움직일 수 있어야 합니다).

## 그림 문법 요약 (AI에게 프롬프트와 함께 주세요)

```
[그림 문법] 그림: 평면(또는 공간) 다음에 이름=값을 띄어서 쓴다. 값 안에는 띄어쓰기를 쓰지 않는다.
정의
  a=2,1          소문자: 벡터(또는 조절기 값)       A=0,0  대문자: 점
  AB             정의하지 않으면 B−A 벡터           a=AB@A  시작점이 A인 벡터
  P=A+t*AB       식으로 정의 (위에서 아래 순서로 계산)
설정
  범위=xmin,xmax,ymin,ymax (평면) / 범위=r (공간)
  끌기=A,b                     학생이 끌 수 있는 점·벡터
  슬라이더=t,0,1,0.1;k,-2,2,1   조절기 (이름,최소,최대,간격; 여러 개는 ;)
  보기=이름표:식;식             그림 아래에 실시간으로 나오는 값 (이름표 12자 이내, 띄어쓰기는 _)
  화살표=a,b,AB  선분=AB,BC  다각형=ABCD  직선=P,u  원=C,r  자취=P  숨김=a
  곡선=a*x^2-2*x;2^x            y=f(x) 그래프 (평면, x가 변수, 조절기 값을 넣을 수 있다)
  (공간) 평면=n,d  구=C,r  직육면체=가로,세로,높이 (꼭짓점 A~H가 자동으로 생긴다)
식
  + − * / ^  2a(곱셈 생략)  |v|(크기)  a·b(내적)  √x  π  (x,y) (x,y,z)
  각(u,v) 두 벡터의 각(도)  각선(u,v) 두 직선의 예각  mid(A,B) 중점  div(A,B,m,n) 내분점  cen(A,B,C) 무게중심
  cos sin tan(도 단위)  cosr sinr tanr(라디안)  sqrt abs exp ln log
기타
  그림: /img/abc123.png        교사 화면에서 올린 그림 파일 (조작은 안 됨)
  그림: 없음                   그림 없음
예
  그림: 평면 a=3,-4 끌기=a 보기=a;|a|
  그림: 평면 A=1,3 B=7,0 P=(1-t)*A+t*B 슬라이더=t,0,1,1/6 화살표=A,B,P 보기=|AP|;|PB|;비율:|AP|/|PB|
  그림: 평면 범위=-3,5,-3,6 곡선=a*x^2-2*x 슬라이더=a,-1,2,0.5 보기=꼭짓점_x:1/a
  그림: 공간 직육면체=3,4,12 화살표=AC,AG 보기=ㄱ:|AC|;ㄴ:|AG|
```

## 프롬프트 1단계: 설계표 만들기

```
수학 방탈출 게임의 문항 세트를 만들려고 합니다. 이 게임의 목적은 개념 학습과,
학생이 그림을 직접 끌거나 조절기를 움직이며 개념을 스스로 발견하게 하는 것입니다.
첨부한 교과서 [과목] [단원] ([쪽]쪽)을 보고, md 파일을 만들기 전에 먼저 설계표를 표로 만들어 주세요.

[게임 구조]
- 상자 9개. 상자 1~3은 방 1, 상자 4~5는 방 2, 상자 6~7은 방 3, 상자 8~9는 방 4
- 상자마다 하(교과서 예제)·중(교과서 문제·중단원 마무리)·상(수능·심화) 3문항
- 상자 6~9의 상 문항은 2인 협업: 두 학생이 조건 ㉠, ㉡을 하나씩 나눠 보고 채팅으로 함께 푼다
- 핵심 카드 10장 안팎: 게임 속 비석에서 읽는 개념 정리 카드. 카드마다 연결된 상자 번호(비석)가 있다

[설계표의 열]
상자 번호 | 방 | 상자 이름(개념) | 연결 핵심 카드 제목 |
조작 아이디어(무엇을 끌거나 움직이면 → 어떤 값이나 모양이 보여 → 어떤 개념을 발견하는가) |
하·중·상 문항 아이디어 한 줄씩 | 협업 상자라면 조건 ㉠·㉡을 어떻게 나눌지

[조건]
- 개념 순서는 교과서를 따르고, 숫자는 교과서와 다르게 새로 정한다(유형만 따른다)
- 조작 아이디어는 "보는 그림"이 아니라 "움직이며 발견하는 그림"이어야 한다
  (예: t를 움직여 AP : PB가 2 : 1이 되는 순간을 찾으면, 그때 계수가 1/3, 2/3이다)
- 아직 md 파일은 만들지 말고 설계표만 주세요.
```

설계표를 보고 고칠 점을 말한 뒤, 괜찮으면 2단계로 넘어갑니다.

## 프롬프트 2단계: 핵심 카드 만들기

```
좋습니다. 확정한 설계표대로 핵심 카드 부분을 첨부한 geo-3-1.md의 형식으로 만들어 주세요.
(위의 [그림 문법 요약]을 함께 붙여 넣으세요)

카드 하나의 모양:
# 핵심 카드 · (개념 이름 — 상자의 "- 개념:" 이름과 똑같이)
- 비석: (연결 상자 번호 1~9)
그림: (개념을 움직이며 확인하는 조작 그림 한 줄 — 그림 문법을 따른다)
요약: (한 문장 정의나 공식)
- (설명이나 성질 2~4줄. 그림에서 무엇을 움직여 보면 되는지 한 줄을 꼭 넣는다)

[조건]
- 벡터는 [AB], {a}로, 영벡터는 $\vv{0}$로 쓴다. √, π, θ, °, ²는 그대로 써도 된다
- 그림의 보기= 에는 카드의 공식이 성립함을 보여 주는 값(양쪽 값)을 띄운다
- 그래프가 필요한 개념은 곡선=으로, 사진처럼 조작할 수 없는 그림만 그림: /img/… 를 쓴다
  (올려 둔 그림: [여기에 /img/… 주소와 무슨 그림인지 적기])
```

## 프롬프트 3단계: 문항 27개 만들기

```
좋습니다. 이제 같은 설계표와 핵심 카드에 맞춰 상자 9개 × 하·중·상 = 27문항을 만들고,
머리말·상자·핵심 카드를 모두 합친 md 파일 하나로 주세요. 형식은 첨부한 geo-3-1.md와 똑같이 합니다.

[맨 위 머리말] 세트: 영문 소문자·숫자·하이픈 이름(예: math1-2-3, 기본 세트 이름 geo-3-1 등은 쓰지 않는다) / 제목 / 교과 / 단원 / 출처
[상자 머리] # 상자 N · 이름 / - 방: / - 협업: 예·아니오 (상자 6~9는 예) / - 그림: 없음 / - 개념: (카드 제목과 똑같이)
[문항 한 개의 줄 순서] ## 하(중, 상) → 그림: → 조작: → 문제: → (조건 ㉠: → 조건 ㉡:) → 답 형식: → (보기:) → 정답: → 풀이:

[그림과 조작 — 이 게임의 핵심]
- 27문항 모두 그림: 줄을 넣는다. 문제의 수치와 그림의 수치를 똑같이 맞춘다
- 학생이 그림을 움직이다 보면 답의 실마리를 스스로 찾게 설계한다
  (보기= 에 답을 직접 띄우지 말고, 답을 찾는 데 필요한 중간값을 띄운다)
- 합답형(ㄱ, ㄴ, ㄷ)은 보기= 에 각 진술의 양쪽 값을 띄워, 조작하며 참·거짓을 확인하게 한다
  (예: 보기=ㄱ왼쪽:AB+AF;ㄱ오른쪽:AO)
- 조작: 은 무엇을 움직여 무엇을 보면 되는지 한 문장으로 안내한다. 답은 알려 주지 않는다

[문제 문장]
- 한 줄로 길게 쓰지 말고 \n으로 줄을 나눈다 (조건 → 정의 → 묻는 것)
- 합답형: 문제 끝에 "\n\n[보기]\nㄱ. …\nㄴ. …\nㄷ. …", 답 형식: 오지선다,
  보기: ① ㄱ | ② ㄱ, ㄴ | ③ ㄱ, ㄷ | ④ ㄴ, ㄷ | ⑤ ㄱ, ㄴ, ㄷ, 정답은 번호
- 협업 상자(6~9)의 상: 문제 첫 줄은
  "🤝 두 사람이 조건을 하나씩 나눠 가졌어요.\n채팅으로 조건을 알려 주고 함께 푸세요.\n"로 시작하고,
  조건 ㉠, ㉡을 따로 쓴다. 두 조건을 모두 알아야만 풀린다

[답 형식] 숫자(2√5, 1/2, π/2, -3) | 오지선다(보기 5개를 | 로, 정답은 번호) | 고르기(보기를 쉼표로, 정답도 쉼표로) | 벡터식(-a+2b, 1/3a+2/3b)
  답이 방정식이면 그 방정식에서 나오는 값(좌표, 각, 거리, 넓이)을 묻는 숫자 문제로 바꾼다

[풀이] 두 번 틀리면 보이는 힌트다. 먼저 "그림에서 무엇을 보면 되는지" 한 줄, 그다음 계산 2~3단계, 마지막에 답

[마지막 확인] 27문항의 정답을 다시 계산해 검산하고, 설명 없이 md 파일 하나로 준다
```

## 검사 오류 고치기

교사 화면의 **🔎 검사만 하기**에서 오류가 나오면 이 프롬프트를 씁니다.

```
업로드 검사에서 아래 오류가 나왔습니다. 첨부한 md 파일에서 해당 부분만 고쳐 전체 파일을 다시 주세요.
(여기에 교사 화면의 오류 문장을 그대로 붙여 넣기)
```

## 그림만 바꾸기 (교체용 그래프·조작 그림)

이미 있는 세트의 그림만 다시 만들 때 씁니다.

```
첨부한 md 파일에서 [상자 N의 중] (또는 핵심 카드 '…')의 그림: 줄만 다시 만들어 주세요.
- 목적: 학생이 [무엇]을 움직이며 [어떤 개념]을 발견하게 하기
- 그래프가 필요하면 곡선=으로, 매개변수는 슬라이더=로 둔다
- 문제의 수치와 맞추고, 그림: 줄과 조작: 줄만 바꾼 결과를 준다
(그림 문법 요약을 함께 붙여 넣기)
```

## 좋은 결과를 얻는 요령

- **예시 파일과 그림 문법 요약을 꼭 함께 주세요.** 형식을 말로 설명하는 것보다 훨씬 정확합니다.
- **단계마다 확인하세요.** 설계표 단계에서 조작 아이디어를 고치는 것이 문항을 다 만든 뒤 고치는 것보다 쉽습니다.
- 교과서는 단원 전체가 아니라 그 소단원의 쪽만 주세요.
- 저장하기 전에 **🔎 검사만 하기**로 형식과 정답을 확인하세요. 검사는 정답을 채점기로 직접 채점해 보고 그림 줄도 읽어 봅니다.
- 저장한 뒤에는 그 채널에 적용해, 학생 화면에서 상자 2~3개와 카드 1~2장을 직접 열어 그림을 움직여 보세요.
